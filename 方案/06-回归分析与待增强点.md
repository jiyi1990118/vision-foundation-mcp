## 3. 未实现 / 待增强点

### P0 - 影响复原有效性

#### G-A1 组件类型检测覆盖不足
- **证据**：`ir/types.ts` ComponentType 联合 39 类；`ast-builder.ts` COMPONENT_TYPE_MAP 仅映射存量 11 类（button/input/dropdown/table/tab/card/checkbox/toggle/badge/avatar/unknown）+ REGION_TYPE_MAP 8 类区域 + media 3 类。**~18 类从不产出**：`list / listItem / row / column / grid / toolbar / iconButton / title / subtitle / textarea / radio / select / divider / progress / tag / dialog / drawer / bottomSheet`。
- **影响**：agent 永远收不到"列表/列表项/对话框/抽屉/下拉选择/单选/文本域/分隔线/进度条/标签"等结构--这些是现代 UI 高频组件，缺失直接降低复原保真度。
- **建议**：扩展 `ui-layout-extractor` 检测器识别更多类型（list/listItem 按重复项+容器推断；dialog/drawer/bottomSheet 按遮罩层+居中/边缘定位推断；select/radio/textarea 按 OCR 关键词+几何推断；divider 按细长矩形；title/subtitle 见 G-A2）。这是**当前最大缺口**。

#### G-A2 文本节点未按层级类型化
- **证据**：`ast-builder.ts` OCR 绑定统一产 `type: 'text'`（不区分 title/subtitle/body）；`typography-engine` 推断的层级（title/heading/body/caption）未反映到节点 type。
- **影响**：agent 无法从节点 type 区分标题与正文，需额外推断字号层级；title/subtitle 两类 ComponentType 形同虚设。
- **建议**：ast-builder 文本节点按 `estimatedLevel` 或采样 fontSize 映射 type（title/heading->'title'，次级->'subtitle'，正文->'text'）。

#### G-B1 API 选项缺设计沟通约定的粒度开关 + strict_mode
- **证据**：`vision-analyze.ts` zod options 仅 `build_tree / export_codegen / export_figma / export_markdown / use_llm + quality/target`。**缺**：`detect_layout / detect_component / detect_text / detect_icon / detect_theme / strict_mode`。
- **影响**：agent 无法按需请求"只检测布局，不要主题"等粒度控制；无 strict_mode 做输出 schema 校验，缺字段静默通过。
- **建议**：补 detect_* 粒度开关（控制各 extractor 是否运行，省时）；补 strict_mode（输出前 JSON Schema 校验，缺字段失败而非静默）。

### P1 - 复原完整性 / 交互

#### G-C1 覆盖层（z-index / overlay）未建模
- **证据**：dialog/drawer/bottomSheet 在 ComponentType 中但从不检测；AST 是平面包含树，无 z-index/层叠概念。
- **影响**：模态弹层、抽屉、底部弹窗被误建为普通子节点，agent 无法识别"这是浮层"。
- **建议**：检测遮罩层（半透明全屏区域）+ 居中/边缘定位的卡片 -> dialog/drawer/bottomSheet；AST 节点加 `zIndex?` 或 `overlay?` 标记。

#### G-C2 组件交互态不完整
- **证据**：`variant-engine` 仅推断 button variant + 部分状态（关键词）；无 input placeholder、disabled 灰度、链接 href。
- **影响**：agent 不知输入框的 placeholder 文案、按钮是否禁用、文本是否可点。
- **建议**：input 的 placeholder（OCR 文本+灰色采样）、disabled（灰度+低饱和度检测）、链接（蓝色文本+下划线）。

#### G-D1 CodegenIR.slots 仍空置
- **证据**：`codegen-exporter.ts` `slots: []` 恒空；repeats 有 count 但无 template。
- **影响**：可复用组件模板未提取，agent 重复造组件而非识别"这是同一卡片模板的 N 次实例"。
- **建议**：slots 提取（同构重复项的首项作 template，标为 slot）。

#### G-D2 OCR confidence 丢失
- **证据**：`mappers.ts` `toVisionIRFromLayout` 把 texts 映射为 ocr 时 `confidence: 1`（丢弃原始置信度）。
- **影响**：低置信 OCR 文本（模糊/小字）未标注，agent 无法判断哪些文本可靠。
- **建议**：透传 ppu-paddle-ocr 的真实 confidence 到 VisionOcrItem，文本节点 props 标注。

#### G-D3 图片像素未嵌入（无 use_llm 时）
- **证据**：`image-content-extractor.ts` 仅输出 crop 坐标 + altText，不含图片数据；`use_llm=false` 时 agent 拿不到图片内容。
- **影响**：默认路径下 agent 对 icon/image 内容一无所知（只有坐标），无法复原图像区。
- **建议**：默认输出 crop 的 base64 data URL（限大小，如 <8KB 才嵌入）；或始终提供 VLM 描述（成本权衡）。

### P2 - 鲁棒性 / 验证

#### G-E1 无 strict_mode 输出校验
- 见 G-B1。输出无 JSON Schema 校验，字段缺失静默。

#### G-E2 缺真实图验证
- **证据**：86 个 ui-analysis 测试多用合成 SVG 图；benchmark 用合成 fixture；真实 UI 截图未端到端验证。
- **影响**：启发式（borderRadius/boxShadow/variant/page-type）在真实像素上的准确率未知。
- **建议**：建立真实截图基准集（N 张），跑端到端，人工/LLM 评分结构/视觉相似度。

#### G-E3 大图输出规模未控
- **证据**：复杂 UI 的 AST 可达数百节点，uiReconstruction 体积大。
- **影响**：MCP structuredContent 过大影响传输与 agent 上下文。
- **建议**：精简模式（summary-only：只输出 pageType+stats+顶层结构，不输出全树）；或节点数阈值截断。

#### G-E4 segment 阶段（SAM2）缺失
- **证据**：设计沟通 pipeline 含 segment；当前无。
- **说明**：S6 调研已论证 v1 不接入 SAM2（对矩形 UI 增益≈0，CPU 23s/图）。**有意延后，非缺陷**。

## 4. 已知 best-effort 局限（非缺陷，记录在案）

| 项 | 现状 | 说明 |
|----|------|------|
| boxShadow 颜色 | 取最暗阴影像素（阴影与背景混合色，偏浅） | 存在性指示，非精确色值 |
| borderRadius 精度 | 带描边时近似（量级正确，非精确） | S20 已修复白卡漏检 |
| variant 推断 | 仅 button，依赖 theme 颜色比对 | 非 button 组件归 default |
| page-type confidence | <0.5 降级 unknown，signals 清空 | 保守策略 |
| textColor 采样 | 文本 bbox 最暗显著色 | 真实图有效，纯色图可能采到背景 |
| text 归属 | 中心点落在最小包含节点 | 多行/跨组件文本可能误绑 |

## 5. 优先级建议

```
第一优先（P0，直接提升复原有效性）：
  G-A1 组件类型检测覆盖（list/dialog/drawer/select/radio/textarea/divider/...）
  G-A2 文本节点按层级类型化（title/subtitle/text）
  G-B1 detect_* 粒度开关 + strict_mode

第二优先（P1，复原完整性/交互）：
  G-C1 覆盖层 z-index 建模（dialog/drawer/bottomSheet）
  G-D3 图片像素嵌入（默认路径 agent 拿不到图像内容）
  G-D1 slots 可复用模板提取
  G-C2 交互态（placeholder/disabled/link）
  G-D2 OCR confidence 透传

第三优先（P2，鲁棒性）：
  G-E2 真实图基准验证
  G-E3 大图精简模式
```

### 关键判断
- **G-A1（组件类型覆盖）是当前最大缺口**：39 类中近半从不产出，是"看见"层的覆盖盲区，直接影响 agent 复原。建议优先做。
- **G-A2（文本类型化）低成本高收益**：ast-builder 小改 + typography 已有层级推断，立即提升。
- **G-B1（API 粒度）契合设计沟通原始约定**：补 detect_* 开关让 agent 按需控制，是契约对齐。
- 其余 P1/P2 可按需推进；G-E4（SAM2）有意延后，非缺陷。

> 当前实现度（供 agent 复原）约 **84%**。补齐 G-A1/G-A2/G-B1 后预计达 **~90%**，剩余为交互态/验证类增量。

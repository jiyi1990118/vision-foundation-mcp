# 真实图验证报告

> 对当前 MCP（15 Wave 完成）做真实图端到端验证：构造逼真 UI 图，跑完整真实管线（extractUiLayout CV + extractDesignTokens + orchestrator），检验启发式在复杂输入上的实际表现。
> 目的：暴露合成单测未覆盖的真实缺陷。

---

## 1. 验证方法

- **测试图**：逼真 dashboard SVG（640×480）--蓝色 header + 深色 sidebar + 3 张带边框圆角卡片列表 + 提交按钮 + 真实文本（商品管理/商品列表/商品A-C/提交）。
- **渲染**：sharp SVG -> PNG。
- **OCR**：构造与 SVG 文本位置对应的合成 ocrItems（含真实 confidence）。
- **管线**：跑真实 `extractUiLayout`（sharp CV）+ `extractDesignTokens` + `runUiAnalysis`（orchestrator 全富化）。
- **检查**：uiReconstruction 的 tree/stats/semantics/theme/responsive/repeats/样式/置信度。

## 3. 发现并修复的缺陷（2 项实质问题）

### 3.1 mediaArea 过检（最大噪声）
- **现象**：detectMediaAreas（存量）用 20×20 块 + 15% 边缘密度阈值，带边框 UI 的卡片边框/角落产生 **19 个假图标**（图里无任何图标）。
- **根因**：边缘密度阈值无法区分真实图标（内部图形）与边框碎片；检测器跳过文本重叠块但未跳过边框边缘块。
- **修复**：新增 `image-content/media-area-filter.ts` `filterSolidMediaAreas`--对每个 mediaArea 采样其内部主色与外围背景色，相同则丢弃（无图标实体，只是背景+边缘）。接入 orchestrator（有图时过滤）。
- **效果**：**19 -> 2**（丢弃 17 个假阳性）。
- **不动存量**：filterSolidMediaAreas 在 ui-analysis 层，用 orchestrator 已有的 image，不改 detectMediaAreas。

### 3.2 tag 规则过激进
- **现象**：商品名"商品A"等短文本被 type-enricher 误判为 'tag'。
- **根因**：tag 候选含 `'text'` 类型，短文本+小 bbox 即升 tag。
- **修复**：tag 候选移除 `'text'`（文本节点是标签不是 tag），仅 unknown/container 升 tag。
- **效果**：商品名保持原类型，不再误判。

> 这些是存量 `ui-layout-extractor` 的检测精度问题或语义引擎调优，**不在 ui-analysis 层**，需单独处理。

## 5. 结论

- **真实图验证有效**：暴露了 2 项合成单测未覆盖的实质缺陷（mediaArea 过检、tag 过激进），均已修复（19 假图标 -> 2、商品名不再误判 tag）。
- **ui-analysis 层启发式在复杂图上工作正常**：样式、主题、响应式、重复项、置信度、语义摘要均正确。
- **剩余为存量 detector 精度问题**（table/button 误分类、pageType 调优），需在 `ui-layout-extractor` 或 semantic 引擎单独优化，非 ui-analysis 富化层职责。
- **建议**：后续若进一步提升精度，优先修存量 `detectComponents`（table vs list、button 识别）与 page-type-engine 调参。

## 7. 第三次真实图验证（OCR + 候选叠框，媒体候选器重构）

### 7.1 验证范围

- **样本**：`~/Desktop/UI/` 下同一批 16 张真实移动端截图。
- **OCR 路径**：`PpuPaddleOcrProvider` + `extractUiLayoutForAnalysis` + `runUiAnalysis`，脚本 `scripts/ui-realimage-ocr.ts`。
- **CV-only 路径**：不传 OCR，脚本 `scripts/ui-realimage-check.ts`。
- **可视化**：`scripts/ui-visual-report.ts` 生成原图、OCR + 原始媒体候选、最终 AST + 媒体三栏叠框报告；浏览器实际加载检查 16 case、48 image，无 error case、无横向溢出。
- **自动回归**：`tests/ui-analysis/media-area-detector.test.ts` 覆盖文字 veto、重复侧栏、候选上限后移、无 OCR 长条负例、网格相位、OCR 内嵌海报和页头头像。

### 7.2 修复的问题

| 问题 | 根因 | 修复 |
|------|------|------|
| 真媒体被前 20 个网格噪声挤出 | legacy detector 在完整过滤前 `slice(0,20)` | ui-analysis detector 返回完整排序候选；solidity 过滤后再限 20 |
| 纵向菜单图标粘成超长框后被删除 | 20px cell 的 8 邻域把重复图标串成一个组件 | OCR 行锚定拆分同列、至少 3 行的 leading-icon 序列 |
| OCR 文字/状态栏产生媒体碎片 | 仅单 OCR 框覆盖判断，且缺少状态栏规则 | 累计 OCR 覆盖 + 2px 边缘容差 + 时间文字状态栏抑制 |
| 圆形/轮廓图标被 solidity 误删 | 只比较内部主色与外环背景 | 增加二维前景跨度与象限证据 |
| 被 drawer 裁切的海报漏检 | 窄长大组件被统一 aspect-ratio 规则删除 | 对面积足够、双边至少 4 个工作网格的纵向二维媒体保留 |
| 页头头像与背景粘连 | 20px 全局组件无法分离紧凑高纹理对象 | 增加 10px 高纹理通道，要求边缘密度、灰度方差与二维跨度 |
| 大图片继承无关 nearbyText | 通用 nearest-label 规则同样作用于大媒体 | 大二维媒体不绑定附近 OCR，alt 回退为“图片” |
| 原图/OCR 坐标混用 | legacy extractor 内部固定缩到 400px | `layout-extractor-adapter.ts` 缩放 OCR 输入并恢复文本、间距和媒体 bbox |

### 7.3 最终结果

- UI 专项套件：**65 files / 343 tests 全通过**。
- 单元测试套件：**30 files / 333 tests 全通过**。
- OCR 真实图：**16/16 跑通，无 ERROR、无 diagnostics**。
- CV-only 真实图：**16/16 跑通，无 ERROR、无 diagnostics**。
- 关键地址页 `226`：`title=地址修改`、`button=修改`，返回文字不再误判媒体，最终保留 1 个真实选择图标。
- 关键会员页 `229`：重复侧栏图标、左上头像区域、底部客服图标和右侧被 drawer 裁切的连续宣传 `image` 同时保留；左抽屉不再误分类为 image，宣传图不再继承“消息中心”作为 alt。
- OCR 路径普通页面最终媒体约 1–19 项；密集会员/消息/个人页最多 20 项，且上限在像素过滤后应用。

### 7.4 残余风险

- 无 OCR 路径无法使用文字 veto，媒体噪声显著高于默认 OCR 路径，部分密集页会达到 20 项上限。
- 商品卡片、价格块和复杂文字纹理仍可能被保守地标为 `icon`；当前传统 CV 规则优先避免漏掉真实图标，而非追求检测器级别的语义精度。
- `regions=30` 和 generic container 偏多的问题仍来自 legacy `detectRegions`，本轮按约束未重写该 extractor。
- `229` 的头像以紧凑 icon/media bbox 表达，尚无稳定规则自动提升为 `avatar`；下游仍可根据位置、圆形视觉和附近用户名称复原。

# 我建议再增加一个对 AI 开发极其重要的目录（这是整个项目成功的关键）

由于你的目标是**大量借助本地模型/Claude Code/OpenCode 等 AI 来开发**，我建议在文档之外，再增加一个 **AI Context** 目录，专门为 AI 提供稳定上下文，而不是让 AI 去读几十份设计文档。

例如：

```text
.ai/
├── PROJECT_CONTEXT.md        # 项目总体定位（AI 每次开发必读）
├── ARCHITECTURE_RULES.md     # 架构原则（禁止跨层调用、职责边界等）
├── CODING_RULES.md           # 编码规范
├── MODULE_INDEX.md           # 所有模块及职责索引
├── INTERFACE_INDEX.md        # 所有公共接口定义
├── SKILL_SPEC.md             # Skill 开发规范
├── PROVIDER_SPEC.md          # Provider 开发规范
├── PROMPT_SPEC.md            # Prompt 编写规范
├── JSON_SCHEMA_RULES.md      # Schema 规范
├── TESTING_RULES.md          # 测试要求
└── TASK_TEMPLATE.md          # AI 执行单个开发任务时的标准模板
```

然后每次开发一个模块，只需要给 AI：

> **PROJECT_CONTEXT + MODULE_INDEX + 当前模块设计文档 + TASK_TEMPLATE**

AI 基本就能稳定地产出符合架构的代码，而不会每次都"重新发明架构"。

# 真实图验证报告

> 对当前 MCP（15 Wave 完成）做真实图端到端验证：构造逼真 UI 图，跑完整真实管线（extractUiLayout CV + extractDesignTokens + orchestrator），检验启发式在复杂输入上的实际表现。
> 目的：暴露合成单测未覆盖的真实缺陷。

---

## 1. 验证方法

- **测试图**：逼真 dashboard SVG（640×480）--蓝色 header + 深色 sidebar + 3 张带边框圆角卡片列表 + 提交按钮 + 真实文本（商品管理/商品列表/商品A-C/提交）。
- **渲染**：sharp SVG -> PNG。
- **OCR**：构造与 SVG 文本位置对应的合成 ocrItems（含真实 confidence）。
- **管线**：跑真实 `extractUiLayout`（sharp CV）+ `extractDesignTokens` + `runUiAnalysis`（orchestrator 全富化）。
- **检查**：uiReconstruction 的 tree/stats/semantics/theme/responsive/repeats/样式/置信度。

## 3. 发现并修复的缺陷（2 项实质问题）

### 3.1 mediaArea 过检（最大噪声）
- **现象**：detectMediaAreas（存量）用 20×20 块 + 15% 边缘密度阈值，带边框 UI 的卡片边框/角落产生 **19 个假图标**（图里无任何图标）。
- **根因**：边缘密度阈值无法区分真实图标（内部图形）与边框碎片；检测器跳过文本重叠块但未跳过边框边缘块。
- **修复**：新增 `image-content/media-area-filter.ts` `filterSolidMediaAreas`--对每个 mediaArea 采样其内部主色与外围背景色，相同则丢弃（无图标实体，只是背景+边缘）。接入 orchestrator（有图时过滤）。
- **效果**：**19 -> 2**（丢弃 17 个假阳性）。
- **不动存量**：filterSolidMediaAreas 在 ui-analysis 层，用 orchestrator 已有的 image，不改 detectMediaAreas。

### 3.2 tag 规则过激进
- **现象**：商品名"商品A"等短文本被 type-enricher 误判为 'tag'。
- **根因**：tag 候选含 `'text'` 类型，短文本+小 bbox 即升 tag。
- **修复**：tag 候选移除 `'text'`（文本节点是标签不是 tag），仅 unknown/container 升 tag。
- **效果**：商品名保持原类型，不再误判。

## 4. 剩余已知局限（存量 detector / 语义调优）

> 这些是存量 `ui-layout-extractor` 的检测精度问题或语义引擎调优，**不在 ui-analysis 层**，需单独处理。

| 项 | 现象 | 归属 |
|----|------|------|
| table 误判 | 卡片列表区被存量 detectComponents 误判为 'table'（应为 list/card） | 存量 detector |
| button 误检 | "提交"按钮被误检为 container（detectComponents 未识别为 button） | 存量 detector |
| pageType | 'form'（应为 list/dashboard） | semantic page-type-engine 调优 |
| 残留 icon | 2 个边缘碎片未被 solidity 过滤 | 边界情形 |

---

## 5. 结论

- **真实图验证有效**：暴露了 2 项合成单测未覆盖的实质缺陷（mediaArea 过检、tag 过激进），均已修复（19 假图标 -> 2、商品名不再误判 tag）。
- **ui-analysis 层启发式在复杂图上工作正常**：样式、主题、响应式、重复项、置信度、语义摘要均正确。
- **剩余为存量 detector 精度问题**（table/button 误分类、pageType 调优），需在 `ui-layout-extractor` 或 semantic 引擎单独优化，非 ui-analysis 富化层职责。
- **建议**：后续若进一步提升精度，优先修存量 `detectComponents`（table vs list、button 识别）与 page-type-engine 调参。
